# Gemini Protocol Mailing List

This is the rebuilt archive of the [Gemini Protocol](https://en.wikipedia.org/wiki/Gemini_(protocol)) Mailing List.

It is available as:

* [A static browseable HTML archive](https://mailing-list-archive.gemi.dev/www/), providing the same content as the original Mailman-based web interface used by the mailing list.

* [Clean, reconstructred mbox files](mbox/) containing the full contents all messages.

Various sources were used to completely reconstruct the mailing list and make it available.

## History

The mailing list documents the design and evolution of the [Gemini protocol](https://geminiprotocol.net/docs/), gemtext, companion ideas like robots.txt, various clients and servers, the community as a whole, and much more. When new people learn about Gemini, they often have questions about certain design choices. The mailing list is a great resource into those choices.

This list was active from early 2019 until January 2022 when the server hosting the mailing list, `list.orbitalfox.eu`, suffered a hardware failure.

## Sources (and problems)

All sources used to reconstruct the archive are available in `sources/`. They came from a variety of places:

- [HTML versions of the mailing lists messages](https://web.archive.org/web/20211218034113/https://lists.orbitalfox.eu/archives/gemini/), generated by Mailman, captured by the Internet Archive's Wayback Machine.
- Yearly mbox archives, generated by Mailman, captured by the Internet Archive's Wayback Machine.
- Personal mbox files uploaded by members of the community after `list.orbitalfox.eu` went offline.

Unfortunately, many of these sources are incomplete or have errors:

* About 20% of all messages are missing from the Wayback Machine's HTML captures. Messages from 2019 and late 2021 are especially spotty.
* The Date/Thread/Author pages from the Wayback Machine don't contain links to all messages.
* Mbox files contain truncated messages or are unparsable due to [from-munging](https://en.wikipedia.org/wiki/mbox#mbox_family) or [escaping](https://datatracker.ietf.org/doc/html/rfc3676#section-4.4) issues.
* Mbox files mask sender names or addresses, which can break parsing.
* Mbox files contain duplicate messages.
* Later mbox files were uploaded by community members and contain MBs of superfluous MIME headers (spam score, DKIM, list action headers, etc.) which are many times larger than the message contents themselves. 

## Rebuilding the archive

To rebuild the archive, I first needed to clean and combine mbox sources into complete parsable mbox files. This involved:

* Restoring the "From " message delimiter lines and "From: " MIME header lines.
* Removing 18 duplicate messages (messages with the same `Message-ID` header) and restoring truncated messages,
* Combining multiple overlapping mbox files to create a single comprehensive mbox file for 2021.
* Removing superfluous MIME headers (spam score, DKIM, list action headers) and normalized them to match the few headers Orbital Fox's mbox files used: `From`, `Date`, `Subject`, `In-Reply-To`, `References`, and `Message-ID`.

To be able to restore the HTML interface for the mailing list, need to map each email's Message-ID to the message number Orbital Fox used in the web interface. This also is necessary to rebuild the nested message relationships in the email threads, since Orbital Fox did this with more than just the Message-IDs of the mailing list emails.

We have several sources that preserve different pieces of that connection:

- **Individual HTML message pages saved from the Wayback Machine.** These preserve the original numbered filename, the message contents, and an embedded email `Message-ID`. They provide the clearest connection between an email and its original number.
- **Saved Mailman index pages.** These are the pages that listed messages by date, author, subject, or thread. They preserve numbers for many messages whose individual HTML pages were not saved. The thread pages contain additional information hidden in their HTML.
- **Original Mailman mbox files.** An mbox is a file containing many emails together. Authentic original files preserve message order and duplicate copies, which lets us reproduce Mailman’s numbering for the periods they cover.
- **Subscriber mailboxes and previously cleaned mboxes.** These help recover email contents missing from the original snapshots. However, they may have been sorted or deduplicated, may omit messages, or may contain personal replies that never went through the list. Their positions cannot automatically be treated as original archive numbers.

This allowed us to completely reconstruct the mapping of email message -> HTML message ID. To make this work easier in the future, I added a three custom MIME headers to help link messages in the mbox files to the corresponding message in the original HTML archive. Here is an example:

```
X-Orbital-Fox-Message-Number: 15
X-Orbital-Fox-Url: https://lists.orbitalfox.eu/archives/gemini/2019/000015.html
X-Orbital-Fox-Message-Number-Source: original-mbox-order
```

The `tools/reconstruct.py` script rebuilds the mbox files, and also outputs two XML files which define how the messages are threaded together.

## Publishing the Archive

This repo has 2 scripts which take the reconstructed mbox and XML files and publish them in different formats.\

`tools/publish_html.py` publishing the HTML version, which is essentially identical to the original Orbital Fox Mailman interface, with a few exceptions:

* mbox hyperlinks go to the source mbox in the Github repo
* Message contents where an author would link to a previous mailing list post (e.g. `https://lists.orbitalfox.eu/archives/gemini/2019/000015.html`) have been rewritten to point to this mailing list archive (E.g. `https://mailing-list-archive.gemi.dev/www/2019/000015.html`)

`tools/publish_gemtext.py` publishes a gemtext version of the mailing list archive. I host this output at `gemini://gemi.dev/gemini-mailing-list/`
